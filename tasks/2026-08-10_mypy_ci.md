# Issue #22: CI への mypy 型チェック導入

## 目的

Python の型チェックをローカルと CI の同一コンテナ・同一コマンドで実行し、既存コードの型エラーをゼロにする。

## 受け入れ条件

- `docker compose run --rm app mypy src` がエラーなしで完了する。
- CI の最終アプリケーションイメージで `mypy src` を実行する。
- Python・フロントエンドの既存検証が引き続き成功する。
- 実行時の動作を変更しない。

## TDD

1. `src/tests/test_mypy_infrastructure.py` を先に追加し、固定版依存、設定、Dockerfile、CI、開発者ガイドの期待値を定義した。
2. Docker コンテナで Red を確認するコマンドを実行したが、Docker ソケットへの接続が実行環境の権限で拒否され、テストプロセスの起動前に停止した。
3. mypy の設定と既存コードの型契約を追加し、同じコンテナコマンドで Green と回帰確認を行う。

## 変更内容

- `mypy` を固定バージョンの開発依存として追加する。
- 緩い初期設定と、スタブ不足を許容するモジュールを `mypy.ini` に明示する。
- 暗黙のメソッド契約を既存または局所的な `Protocol` で表現する。
- 最終 Docker イメージへ開発依存と mypy 設定を含める。
- CI と開発者ガイドへコンテナ内の実行方法を追加する。

## 対象外

- `strict = true` の有効化。
- TypeScript の型チェック強化。
- 実行時の動作変更やリファクタリング。

## 2026-08-10 追加対応

- 依頼者検証で判明した63件の型エラーを、型注釈、局所的な `Protocol`・`TypedDict`・`cast` と最小範囲の `type: ignore` で解消した。
- `PYTHONPATH=src .venv/bin/mypy src` は `Success: no issues found in 69 source files` で完了した。
- `PYTHONPATH=src .venv/bin/python -m unittest discover -s src/tests` は、実行環境でソケット作成が禁止されているため18件が `PermissionError: [Errno 1] Operation not permitted` となり、その後 `TestClient` 利用テストで停止した。
- 上記の環境依存テストを除いた161件は一括実行で成功し、サーバー互換性テストの非ソケット5件も個別実行で成功した。
