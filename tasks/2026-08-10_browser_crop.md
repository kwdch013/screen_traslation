# Issue #27 ブラウザ内クロップ

## 目的

共有映像の一部をブラウザ上で選択し、選択領域だけを OCR 対象として送信する。翻訳結果はクロップ画像基準の座標へ選択領域のオフセットを加え、元の共有映像上へ重畳する。

## 受け入れ条件

- プレビュー上のドラッグで単一の矩形領域を選択・再選択できる。
- 選択時はクロップ後の寸法で JPEG を送信し、解除時は動画全体の送信へ戻る。
- クロップ画像基準の翻訳領域が元動画上の正しい位置へ表示される。
- 選択領域を動画実解像度とともに保存し、同じ解像度の共有開始時だけ復元する。
- 取得できる場合は共有元ラベルも保存・照合し、同じ共有元である可能性を高める。
- 共有中に動画実解像度が変化した場合は選択を解除し、動画全体の送信へ戻る。
- フロントエンドの lint・test・build と Python 回帰テストが成功する。

## 対象外

- 複数領域の同時選択
- サーバー側でのクロップ処理
- OCR 精度調整
- タッチ操作固有の細かな最適化

## 作業記録

- 指定のPython回帰テストは、ネットワーク隔離環境でソケット生成が拒否され、`WebCaptureServerTest` の12件が `PermissionError: [Errno 1] Operation not permitted` となった。Pythonコードは変更していない。
- PR #50 のレビュー修正はTDDで進め、クロップ変更時の旧結果、実解像度変更、無効ドラッグ、共有元ラベル照合の再現テストが実装前に失敗することを確認した。
- クロップ変更時は表示中の結果だけを即座に消し、現在の送信寸法と一致しない遅延結果を重畳しないようにした。字幕履歴はログとして維持し、新しい結果の受信も継続する。
- 結果にはクロップ位置の識別情報がないため、同じ寸法で位置だけが異なるクロップへ変更した場合は新旧を区別できない。サーバー側の契約拡張は今回行わず、必要になった場合は別Issueで検討する。
- 動画の実解像度変更時はクロップと保存値を解除し、全体送信へ戻す定義済みの挙動とした。
- 極小選択、letterbox外、単純クリックは無効操作として無視し、既存のクロップ選択を維持するようにした。
- 共有元ラベルを取得できる場合は保存値との一致を復元条件へ追加し、取得できない場合は実解像度だけの判定へフォールバックするようにした。
- `useScreenCapture.ts` の責務過多は既存構造に起因するため今回は分割せず、後続Issueでの分割検討が必要な課題として記録する。
- レビュー修正後の検証では、`npm run lint`、`npx vitest run`（9ファイル・78件）、`npm run build` がすべて成功した。
