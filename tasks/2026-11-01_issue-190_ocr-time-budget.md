# Issue #190 OCR前処理の処理時間予算と病的入力の打ち切り

- Base/Merge target: `develop`、ブランチ `task/190-ocr-time-budget`。親 #76、関連 #109 / #110 / #182。

## やったこと
- 測定: `server/tests/tools/measure_ocr_time.py`(compose `measure` profile、2 CPU)。改善前(前処理なし)・#182後本Task前・本Task後を標準ROIと全画面で比較。表は docs/v1.0/testing.md。
- `engines/tesseract_runner.py`: Tesseractを自前の子プロセスで実行。stdin入力、プロセスグループごとSIGKILL、wait回収、期限超過は`OcrTimeoutError`(pytesseractはkill後にwaitせず残留し得るため置換)。
- `engines/robust_ocr.py`: 最初の認識は2.0秒(前処理込み)、追加候補は1.0秒−経過、残り0.15秒未満は不実行。追加候補の期限切れは取得済み結果を返す。ROI上限超の画像は`OcrInputTooLargeError`。Tesseractを単一スレッド。
- `engines/ocr_preprocess.py`: 拡大後画素数の上限を600万→400万(標準ROI最大の3倍拡大=約346万画素を維持)。
- 試験: 単体(偽`sh`コマンド・注入時計)、結合(実Tesseractの全面ノイズ・全画面縞・サーバー経由、子プロセス/zombie/スレッド残留なし、直後のフレームが処理される)。

## 結果の要点
- 標準ROI(最大1280x300)のp95は約0.7秒未満で、OCR予算1000 msに収まる(単体OCR、共有ホスト、予備測定。最終は#109)。
- 全面ランダムノイズは約2.07秒で打ち切り(従来44〜127秒)。全画面の複雑背景も2.0秒で打ち切り(従来14秒、改善前でも約2.6秒)。これは予算未達としてOwnerへ提示(testing.md)。

## 試して採用しなかったこと
- 大きい画像ではグレースケールを先に試す順序: 縞背景の全画面で認識が約1.7秒かかり効果なし(Tesseractの時間が倍率に単調でない)。
- 倍率の引き下げ: 標準ROIは予算内で、精度(#182)を落とすため不採用。

## mutation
| 変異 | 結果 |
| --- | --- |
| kill後のwait回収を外す | 検出(単体2件: returncode未設定) |
| 独立プロセスグループをやめる(孫が残る) | 検出(孫が生存してパイプを保持→`communicate`が戻らず試験がtimeout=ハングとして検出) |
| OCR期限 2.0→4.5秒 | 検出(5秒失効との整合試験) |
| 拡大後画素数上限 400万→600万 | 検出(2件) |
| Tesseractのスレッド数 1→指定なし | 検出 |
| ROI上限超の拒否を外す | 検出 |
| 追加候補の1.0秒予算を外す(全体期限を流用) | 検出(2件) |
| 期限超過を「Tesseractなし」エラーへ丸める | 検出(2件) |
| 前処理時間を期限から差し引かない | 検出(3件) |
| 倍率 3→2 | 検出(2件) |
| Tesseractへ渡す期限を1000倍にする(結合) | 検出(標準ROIサイズのノイズが打ち切られず`OcrTimeoutError`未発生) |

最初の結合試験は1.0秒の期限を前処理(1920x1080のノイズで約1.3秒)だけで使い切り、Tesseractを起動せずに通っていた。上のmutationで発覚し、起動回数を数えて標準ROIサイズのノイズでkillを検証するよう修正した。
