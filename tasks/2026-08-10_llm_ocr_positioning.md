# Issue #24: LLM OCR の文字領域座標対応

## 目的

LLM OCR から文字領域ごとの画像ピクセル座標を取得し、既存の SSE とフロントエンド重畳表示へ渡す。

## 受け入れ条件

- 矩形付きJSON配列から複数の `TextRegion` を `positioning: available` で生成する。
- 説明文や Markdown コードフェンスを含む応答からJSON配列を抽出できる。
- 不正な要素だけを破棄し、妥当な要素を維持する。
- JSONを解釈できない場合、または妥当な要素がない場合は従来の疑似領域へ安全に劣化する。
- `FallbackOcrEngine` の既存クリーニングを座標付き領域にも適用する。
- 複数の座標付き領域が SSE で配信され、フロントエンドで重畳される。

## TDD

1. LLM HTTP 層を既存の `_transport()` でモックし、構造化応答、部分的な不正要素、非JSON、範囲外、必須項目欠落、空応答のテストを先に追加した。
2. 構造化応答の2テストが、応答全体を単一の `unavailable` 領域にする既存実装に対して失敗することを確認した。
3. 応答パーサーとプロンプトを実装し、関連する Python テスト22件が成功することを確認した。
4. SSE の複数領域契約と React の複数重畳表示を回帰テストで確認した。

## 実装方針

- OpenAI 互換バックエンドごとの対応差を避けるため `response_format` は追加せず、プロンプト指示と応答パースで対応する。
- パース処理は既に300行を超えている `ocr.py` から `llm_ocr_response.py` へ分離する。
- 座標は送信画像の左上を `(0, 0)` とする。小数値は領域を欠けさせないよう外側の整数ピクセル境界へ広げる。
- 画像範囲外、非数値、幅・高さが0以下、空テキスト、必須項目欠落の要素は個別に破棄する。
- 妥当な要素が1件も残らない場合だけ、応答の生テキストを既存の疑似領域へ格納する。

## 対象外

- 新しい LLM プロバイダーやモデルの追加。
- Tesseract 側の変更。
- プロンプトチューニングによるOCR精度改善。
- `verification/` での実モデル精度評価。自動テストでは再現できないため、既存評価フローを使う手動確認とする。
- API固有のJSONモードの利用。
