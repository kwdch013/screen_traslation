# ADR-0005 単一セッション・世代・入力上限の候補

## 状態

2026-10-30、**設計採用**。単一所有者・処理1/待機最新1・client-monotonic expiry・session/generation/frame/revision検査を採用する。競合・障害注入は未実施。schemaとfixtureは #62/#63/#64 で確定する。[索引・検証課題](README.md) / [基本・詳細設計](../architecture.md)。

## 対象要件

REQ-F-003、REQ-F-006、REQ-F-007、REQ-F-008、REQ-F-009、REQ-F-010、REQ-NF-001、REQ-NF-004、REQ-NF-005、REQ-NF-007。

## 背景

認証済みでも別端末のセッションを操作できてはならない。過負荷や停止後の遅延結果、辞書更新前の結果が現在の画面へ表示される危険を防ぐ。処理件数を積み上げる方式は要件と合わない。

## 比較

| 候補 | 利点 | 制約・今回の判断 |
| --- | --- | --- |
| 単一調停者・単一所有者、処理1/待機最新1 | 所有権と世代の変更を一箇所で順序付けられる | 複数workerへ水平拡張する設計ではない。推奨候補 |
| 無制限FIFO・受信順に全処理 | 実装が単純 | 古い画像が蓄積し遅延/メモリ予算を破るため不採用 |
| 最新接続でセッション奪取 | 再接続処理を短縮できる | 2台目拒否・暗黙奪取禁止に反するため不採用 |
| 多worker・共有ストアで調停 | 将来の分散処理には適する | v1.0単一セッションには運用と競合が増える。優先しない |

## 採用方式

Linuxプロセス内の単一調停者が認証IDとsession所有権を結び付け、開始を原子的に判定する。使用中の2台目、異なる所有者/sessionの制御/画像を拒否する。端末roleは自分のsessionだけ操作でき、管理roleだけが管理APIを呼ぶ。停止/切断で解放後の明示開始だけで交代する。推測可能なsession IDだけで所有者判定しない。

契約version・session・generation・frame連番・辞書revisionを照合する。対象再選択/停止/設定更新で以前の結果を無効化し、処理が直ちに中断できなくても配信/表示しない。client取得時単調時計で5秒expiryを判定し、異なるhost clockを減算しない。無通信5秒以内で切断検知、検知から1秒以内に表示消去、10秒以内に所有権解放。停止/再選択/対象消失から1秒以内に表示消去し、復旧後も自動送信を開始しない。

取得/送信の既定2 fps・設定1～5 fps、送信は取得以下、静止10秒の新規画像0枚を守る。ROIは64×32～1920×1080・最大2,073,600画素・PNG/JPEG符号化後4 MiB以下で、超過時は無断縮小せず再選択を促す。受信時は認証と実受信長判定をdecode/OCRより先に行い、declared lengthを信用せず形式・画像header・展開後画素数を検査する。処理1/待機最新1で古い待機を置換する。

Windows履歴はメモリ内で最新100件。停止中は閲覧できるが再選択・新セッション・終了で消去する。現在表示の失効と履歴寿命を区別し、通常ログ/サーバーへ履歴を永続化しない。

## 検証と確定担当

Q-04/Q-05/Q-09について #57/#62/#64 がスキーマ、状態遷移、heartbeat、処理キャンセル/子プロセスの時間上限、接続数/制御メッセージ長を決める。#72/#73/#74/#78/#94/#98/#108はACC-02/ACC-04/ACC-08/ACC-11/ACC-12で、並行開始/停止、順序逆転、旧revision/未対応版、巨大/偽装/破損画像、101件履歴、2端末再接続を試験する。上限境界ちょうどと+1を区別し、テストのskipを合格にしない。

## 影響

単一アクティブセッションは認証機能の代替ではない。トークン失効、接続終了、実行中処理の結果破棄を連動する必要がある。CPU 2/メモリ4 GiBをプロセスと子プロセスに適用し、クライアント512 MiBの予算も監視する。認証済みの悪意ある入力にも上限を適用し、再試行・キュー・子プロセスを増やさない。保持期間の変更は機微情報要件の変更として扱う。
