# ADR-0004 TLS終端・端末認証・資格情報管理の候補

## 状態

2026-10-29、提案。TLS・発行/失効・OS保護の実証は未実施。#57/#75で運用と具体値を確定する。[索引・検証課題](README.md) / [脅威モデル](../security.md)。

## 対象要件

REQ-F-009、REQ-F-010、REQ-F-012、REQ-NF-006、REQ-NF-007、REQ-NF-009。

## 背景

LANも未認証端末・盗聴・偽サーバーを想定する。全ネットワークAPIとストリームにTLS/端末認証が必要であり、端末認証と管理権限を分ける。一般公開、マルチユーザー認証基盤、証明書購入を前提にしない。

## 比較

| 候補 | 利点 | 制約・今回の判断 |
| --- | --- | --- |
| アプリ（ASGIサーバー）でTLS終端 | コンテナ数と認証境界が少なく、平文の内部ネットワークを作らない | 証明書差し替え/接続終了の運用が必要。推奨候補 |
| リバースプロキシでTLS終端 | 証明書更新・前段制限を独立管理できる | プロキシ迂回経路/転送ヘッダー/内部通信の保護が増える。代替候補 |
| TLS + 不透明な端末/管理別トークン | 失効台帳と権限を単純に管理できる | Bearer漏えいは使用可能な間のなりすましになる。推奨認証候補 |
| mTLS | 端末鍵の保有をTLSで確認できる | 発行/保管/更新/失効の配布負担が増える。トークン案不成立時の比較先 |
| Cookie/JWT | ブラウザや分散認証で使いやすい | 新版はネイティブ単一利用で、Cookieのブラウザ経路やJWT失効が追加課題。優先しない |

## 採用候補

既存採用技術のFastAPI/Uvicornを出発点にアプリ内TLS終端を比較する。TLS 1.2以上を候補下限にし、実際のPython/OpenSSL設定とTLS 1.3対応・無効プロトコルを #57/#75 で確認する。平文起動へフォールバックしない。HTTP→HTTPSリダイレクトを画像/secret送信の保護とみなさず、クライアントは最初からHTTPS/WSSだけを使う。

資格情報は暗号学的乱数の256 bit以上の不透明トークンを提案する（要件にない設計値で、#57/#75で確定）。端末用と管理用を別発行し、台帳には識別子・検証用ハッシュ・権限・期限・失効状態を保持、平文の再表示をしない。管理者だけがローカルの認証済み管理手段/専用管理権限で発行・失効を行う。初回管理資格情報はsecretで供給し、未設定/共通初期パスワードで起動しない。管理資格情報を一般クライアントの通常保存領域へ配らない。

端末資格情報はWindows DPAPIのCurrentUser保護を候補にし、ファイルACLも制限する。サーバーのTLS秘密鍵・管理secretはDocker Compose secrets等の読取専用ファイルで与え、イメージ・Git・コマンド引数・query・ログへ含めない。secretの元ファイルの所有権/バックアップ権限は管理者が保護する。Compose secretsだけでホストの保存時暗号化を保証しない。

## 検証と確定担当

Q-07/Q-08/Q-09を #57/#75 が設計し、#74/#88/#103/#108でACC-05/ACC-12/ACC-14を検証する。購入なしの検証用私設CAとSAN付きサーバー証明書を発行し、CAの公開情報を別の確認済み経路でクライアントへ登録する。自己署名サーバー証明書の厳格なpinningも比較候補だが、名前・期限・更新確認を省略しない。TLSの信頼確立前に資格情報を送らない。

正常/未信頼/SAN不一致/期限切れ、CAとleafの更新・旧信頼の撤去・更新失敗時の停止を試験する。証明書変更を自動承認しない。鍵漏えい時は旧接続も閉じ、CA/leaf再発行と信頼再配布を行う運用を候補とする。失効トークンは全HTTPと既存WSSの操作/配信へ反映する。反映期限・台帳再読込・処理中結果の廃棄時点を #57/#75 で具体値にし、失効直後と期限境界の両方を試す。未規定の期限を合意済み扱いにしない。

## 影響

証明書配布/更新とトークン発行/失効は別の運用である。Hostは外部設定の許可一覧で検証し、Originがある要求は許可一覧で制限する。ネイティブのOriginなし要求も認証必須とし、ブラウザCookieやCORSを認証の代用にしない。認証失敗の応答にsecretや内部状態を含めない。接続数/試行頻度/管理入力の上限は #57/#62 で確定する。HTTPプロキシ方式へ変更する場合は、直通経路を閉じ、信頼する転送元と内部通信保護を脅威モデルに追記する。

## 根拠

2026-10-29確認: [DPAPI](https://learn.microsoft.com/en-us/dotnet/standard/security/how-to-use-data-protection)はユーザー/マシンに基づく暗号化を提供する。[Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/)は明示したサービスへファイルを渡す仕組みである。[Python ssl](https://docs.python.org/3.14/library/ssl.html)をTLS設定の確認先とする。[Uvicorn公式設定](https://uvicorn.dev/settings/)はTLSの鍵/証明書とWebSocketのサイズ/待機設定を提供する。実装時は固定版で設定の可用性と挙動を再確認し、既定値のまま要求を満たすとは仮定しない。本書の終端・トークン案は要求からの提案で、UvicornのTLS/失効試験完了を主張しない。
