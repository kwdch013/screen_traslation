# ADR-0003 新旧共存とコア抽出の候補

## 状態

2026-10-30、**設計採用**。Windows client / Linux server / shared contractsを同じrepository内に分離し、翻訳コアをport経由で段階抽出する。抽出・新旧回帰は未実施で、#68/#69が構造とCIを整える。[索引・検証課題](README.md) / [基本・詳細設計](../architecture.md)。

## 対象要件

REQ-F-004、REQ-F-008、REQ-F-012、REQ-NF-007、REQ-NF-009、REQ-NF-010。

## 背景

同一repoのclient/server/contractsで開始し、受入前に既存Web版を撤去しない。既存 `src/app/ocr.py`、`translator.py`、`glossary.py`、`pipeline.py`、`contracts.py` 等の知見を使いつつ、Web専用のセッションや取得/表示とLinuxコアを分ける必要がある。現行仕様は[仕様書](../../../specification.md)を参照する。

## 比較

| 候補 | 利点 | 制約・今回の判断 |
| --- | --- | --- |
| 境界ごとの段階抽出とアダプター | OCR/翻訳/辞書の既存検証を再利用し、新旧契約を分けられる | 共通部の変更がWebへ波及するため回帰が必須。推奨候補 |
| serverへ全コピー | 当初は旧版へ影響しにくい | 辞書修正/依存/機微情報対策が二重管理になる。短期の比較用以外は優先しない |
| WebAppServiceをそのまま外部公開 | 既存経路を利用できる | ループバック前提・Web契約・機微ログを引き継ぐ危険がある。不採用候補 |
| 全面書き直し/別repo | 新方式を独立設計できる | 回帰資産を失い、repo分割は要求外。採用しない |

## 採用方式

OCR/翻訳/辞書の副作用をadapterに閉じ、小さなport単位で抽出して旧Web adapterと新server adapterから呼ぶ。Windowsが取得/選択/重畳/履歴、Linuxが認証/セッション/OCR/英日翻訳/辞書を担当する。`contracts/`は両言語の版付き外部契約とfixture、Python Protocolは内部境界とする。`client/`・`server/`・`contracts/`を同repo内に配置し、#68/#69で依存と回帰を確定する。本Taskではソース移動をしない。

既存`JsonlTranslationLogger`等の内容保存、任意LLM外部接続、Web用設定既定値を新版へ引き継がない。新版は機微内容を永続ログに残さず、英日Tesseract/Argosを使う。旧Web版の利用法を変更せず、新版の資格情報・モデル・設定/辞書は別namespace/保存先へ分離する。同一の永続ファイルを旧新両方から更新しない。

## 検証と確定担当

Q-06/Q-09/Q-11を #57 が境界・保存先・互換範囲へ落とし、#69/#83/#84/#85/#106で旧revision拒否、原子的更新、次フレームへの反映、復旧とWeb回帰を検証する。抽出前後で同じ人工入力のOCR領域・辞書適用・エラーを比較し、ログ検査で架空の原文/訳文/secretの不在を確認する。ACC-09/ACC-12/ACC-14が判定先。

## 影響

共有部の破壊を防ぐため、機能移動前に契約fixtureと回帰を揃える。旧版と新版の起動/テストを別に記録する。#26はWeb回帰、#49は任意LLM評価として維持する。抽出が要求を満たさない場合は限定的複製を代替として比較し、差分管理と移行期限を #57 に記録する。受入前の削除や依存の無断変更をしない。

## 根拠

2026-10-29確認: リポジトリ内の[現行開発ガイド](../../../developer_guide.md)、[現行仕様](../../../specification.md)、[要件の範囲](../../../../requirements/version_1/requirements.md)を根拠にした設計判断。既存のコード構造は再利用候補の根拠であり、Python 3.14の全依存互換性・新版の安全性が検証済みという意味ではない。
