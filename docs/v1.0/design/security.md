## 対象範囲と攻撃者

Windowsクライアント、LAN上のLinuxバックエンド、設定/辞書/モデル/資格情報の導入・保存・復旧を対象とする。既存Web版はループバック前提の別契約として維持し、認証なしの既存経路をLAN公開する根拠にしない。一般公開やマルチユーザーは対象外でも、LANを信頼済みとは扱わない。

未認証のLAN端末、盗聴/中間者、資格情報を入手した端末、正規端末による誤操作/巨大入力、悪意ある取得対象の画像、改ざんされた依存/モデル/配布物を想定する。OS管理者権限や端末自体の完全侵害はアプリだけで防御できない残余リスクとし、無制限な資源投入やOS保護回避は想定しない。単一利用者でも管理権限と端末権限は分ける。

## 認証とTLS

[ADR-0004](adr/0004-tls-credentials.md)のアプリ内TLS終端と端末/管理別の不透明トークンを推奨する。全HTTPとWSSの接続時、および既存接続の操作/配信で資格情報と失効を評価する。health/readyにも例外を作らず、資格情報の失効を接続の張り直しまで延期しない。認証の成功だけではセッション所有権・管理権限を得ない。

証明書は名前・期限・信頼を検証し、未信頼なら送信を止める。検証用私設CAを使えば購入は不要で、CA公開情報の別経路確認、SAN付きleaf発行、信頼登録、正常/不正条件、leaf/CA更新、旧信頼撤去の順に試験できる。更新失敗時は停止し、検証無効化やHTTPへ切り替えない。TLS鍵の侵害時は旧接続終了と鍵/証明書の再発行、信頼再配布を行う候補とする。失効トークンや侵害鍵のバックアップを復元して有効状態へ戻さない。

資格情報の発行は管理者に限定し、端末用と管理用を別管理する。再発行/更新時は新資格情報をOS保護で保存して確認後に旧資格情報を失効する手順を候補とする。漏えい時は即時失効・既存接続停止・再発行を行う。具体的な反映期限・証明書/トークンの有効期間・許容する更新重複期間・管理API権限表・初期管理手順は #57/#75 が確定し、Q-07/Q-08の境界試験へ反映する。未確定値を要求の既定値として追加しない。

接続先・ポート・許可Host/Origin・信頼情報・secret参照・保存先は設定/環境変数/secretで与える。秘密値そのものはsecret/OS保護へ置き、Git・平文の設定例・画像証跡・例外ログへ書かない。実機未設定なら接続試験をskipと記録し、製品合格には数えない。

## データ寿命と入力の扱い

画像・原文・訳文は通常メモリ処理のみ。通常/失敗/例外時とも永続内容ログを出さない。相関ID、状態コード、件数、サイズ、処理時間など内容を含まない運用情報だけを候補にし、トークン/ヘッダー/URL queryの一括ログを禁止する。明示許可した匿名fixture以外の画面を試験証跡へ添付しない。終了/無効化時は参照とバッファを解放するが、OSやランタイムの物理的な完全消去までは保証しない。

履歴はWindowsの最新100件をメモリ保持し、停止中閲覧可、再選択/新セッション/終了で消去する。古い現在表示の失効と履歴を混同しない。設定/辞書だけはLinuxで永続化して検証付きバックアップを提供し、秘密鍵/資格情報は分離して保護する。クラッシュダンプやOSのswap等はホスト管理者の保護対象で、アプリの内容ログ禁止で防げたと主張しない。

画像をOCRするだけでコマンドやパスとして実行しない。OCR文字列・辞書・結果は信頼できない文字列として表示/検証し、シェル実行や任意のマークアップ解釈へ渡さない。新規LLM/VLMは対象外のため、LLM固有の対策を既定経路へ架空に追加しない。入力境界/処理待ち/失効の具体的契約は [ADR-0005](adr/0005-session-lifecycle.md)と #62/#64 へ引き渡す。

## 残余リスク

- 端末やホスト管理者が侵害された場合、メモリ上の内容/復号済みsecretへアクセスされ得る。DPAPI/secretは同一権限の悪意あるプロセスへの完全隔離ではない。
- 正常な資格情報を盗んだ攻撃者は失効までなりすませる。単一所有権・権限分離・有界処理で影響を抑え、失効反映期限は #57/#75 で決定・検証する。
- 自己取得除外はOS/対象/取得APIに依存し、撮影や別の悪意ある取得を防ぐDRMではない。#58/#59の未実施条件を対応済みとしない。
- 画像/モデルを扱う依存に未知の欠陥があり得る。固定版/digestと資源制限は完全防御ではなく、更新時の回帰と破損拒否を継続する。
- ネットワーク輻輳/ホスト障害の完全排除はしない。切断検知・表示消去・有界再試行・明示再開で古い情報を残さない。制御メッセージ/接続試行の具体的上限は #57/#62 に残る。
- 私設CAの初回配布経路が侵害されると偽サーバーを信頼し得る。信頼情報の別経路確認が必要。試験用自己署名コード署名は公開発行元の信頼を意味しない。
